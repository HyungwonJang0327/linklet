| L5 | 복수형 | **지금은 지원하지 않는다.** 한국어·일본어는 복수형이 없고 영어만 필요하다. 첫 영어 개수 문구(F13 목록)가 생길 때 `Intl.PluralRules` + 키 접미(`_one`/`_other`) 방식으로 `t()` 를 확장한다(확장 지점). 그 전까지 영어 문구는 개수에 중립으로 쓴다 |
| L6 | 서버·클라이언트 | 사전은 로케일별 동적 `import()` 로 로드(`getDictionary(locale)`) — 클라이언트 번들에 한 언어만. 서버 컴포넌트는 `getDictionary` → `createT(dictionary)`. 클라이언트 컴포넌트는 `I18nProvider`(layout 이 사전을 내려줌) + `useT()`. 둘 다 같은 `createT` |
| L7 | 초기 키 범위 | **기반 키만** (사용자 결정 2026-11-17): `errors.{CODE}` — `ERROR_CODES` 10종 + `errors.UNKNOWN`(E3 폴백) 각각 "다음에 할 수 있는 행동" 문장 / `common.*` 소수(앱 이름·다시 시도·닫기·취소·확인·뒤로·불러오는 중) / `metadata.title`·`metadata.description`. 화면 키는 각 기능 이식 때 그 기능이 세 언어를 **동시에** 추가한다(L3 이 강제). 기존 676키는 옮기지 않는다 — 폐기 화면(QnA·요금제 등)과 옛 문구가 많다 |
| L8 | enum → 키 매핑 위치 | 한 곳에서만(함정 11). `errors.{CODE}` 처럼 **shared 의 값**은 `shared/i18n/keys.ts`(`errorMessageKey(code): DictionaryKey`). Prisma enum(`WishlistCategory`·`InquiryStatus` 등)은 **그 기능 폴더**(`features/{x}/i18n-keys.ts`)에서 `category → 'wishlist.category.birthday'` 로 매핑하고, enum 값 전부가 사전 키에 있는지 그 기능의 단위 테스트가 고정한다. DB enum 값(소문자)을 문자열 결합으로 키에 끼워 넣지 않는다 |
| L9 | 테스트 | `shared/i18n` 단위 테스트: (a) 세 사전의 키 집합 동일(타입 + 런타임 둘 다 — 런타임은 평탄화 비교), (b) **모든 키에서 세 언어의 플레이스홀더 집합이 같다**(2026-11-10 기준선에서 실측한 `{title}` 미치환 버그 재발 방지), (c) `errors.*` 키가 `ERROR_CODES` ∪ `UNKNOWN` 과 정확히 1:1, (d) `t()` 치환·누락 키 반환·`{{` 미치환 확인, (e) 빈 문자열 값 없음 |

## 이유

- 기존 앱의 결함 세 가지(키 타입 없음 → 오타가 런타임에 키 문자열로 노출, 사전 `{title}` vs `t()` `{{key}}` 불일치, `t() || '한국어'` 죽은 fallback 40곳)는 모두 "키·플레이스홀더가 타입과 테스트로 묶이지 않아서" 생겼다. TS 사전 + 파생 타입이 셋을 한 번에 막는다
- 라이브러리 없이 가는 이유: 필요한 기능이 작고, 언어 경로는 이미 `proxy.ts`(F05)·`[locale]` 세그먼트로 처리하기로 했다. next-intl 은 라우팅·미들웨어를 자기 방식으로 요구한다
- 초기 키를 좁히는 이유: 화면 문구는 디자인 시안(`design/mockups`)과 캐주얼 컨셉에 맞춰 새로 쓴다. 옛 문구를 옮기면 "번역은 있는데 화면과 안 맞는" 상태가 된다. 세 언어 동시 추가를 타입이 강제하므로 나중에 빠질 위험이 없다

## 기각된 대안

- **JSON 사전 + `resolveJsonModule` 타입** — 플레이스홀더 인자 타입이 약하고 주석을 못 쓴다 (사용자: TS 선택)
- **기존 676키 전부 이식** — 폐기 화면 키 다수, 새 화면 문구와 불일치 (사용자: 기반 키만)
- **next-intl / i18next** — 번들·라우팅 결합, 결정 없는 의존성
- **복수형을 지금 구현** — 쓰는 곳이 아직 없다. 필요할 때 확장

## 확장 지점

- 새 화면: 그 기능의 키를 `ko.ts` 에 추가 → `en.ts`·`ja.ts` 가 컴파일 에러로 누락을 알려준다 → 세 언어 채움 → 플레이스홀더 테스트가 자동으로 검사
- 복수형(L5): `Intl.PluralRules(locale).select(n)` 으로 `key_one`/`key_other` 선택하는 `tn(key, count, params)` 추가
- 언어 추가: `LOCALES` 에 코드 + 사전 파일 1개 + Prisma enum 마이그레이션 + `proxy.ts` 협상 목록
