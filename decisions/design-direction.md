# UI 시각 방향 (v2 리디자인)

## 결정

**방향 B — 깨끗한 캔버스** (`design/mockups/direction-b.html`)를 v2의 시각 방향으로 채택한다.

- 색: 흰 배경 `#FFFFFF` · 잉크 `#111318` · 보조 `#5B6270` · 강조 파랑 `#2A4FE0` (다크: `#0E1015` · `#EDEFF3` · `#9AA1AE` · `#7F9CFF`). 최종 값은 `decisions/design-tokens.md` 에서 확정
- 모양: 반경 8·10·12, 그림자 없음, 1px 선과 간격만으로 위계
- 밀도: 공유 페이지 2열 그리드, 내 목록 2열(모바일)·3열(데스크톱)
- 타이포: 시스템 산세리프, 제목 24/700, 본문 14 — **단, 공유 페이지는 본문·아이템 제목 15px 이상** (조건 1)

### 채택 조건 (핵심 화면 시안 단계에서 반영)

1. 공유 페이지 글자 크기 15px 이상, 받음 배지에 밝은 테두리(어두운 상품 사진 위 3:1) — designer 검토 medium
2. 빈 상태·랜딩의 온도감(문구·일러스트)을 따로 검토 — B의 "도구적·차가움" 위험 보완
3. 세 안 공통 지적 반영: 공유 페이지 헤더 위계(소유자 이름 키우고 아바타 40px), 받음 상태를 `aria-label` 에 포함, `--c-border-strong` 3:1, 아바타 터치 영역 44px, "공개" 반복 표기 제거(비공개만 자물쇠)

## 이유

- 토큰 종류가 가장 적고(배경=면, 그림자 없음) 라이트·다크 구조가 같아 Phase 1 토큰 적용과 F29 테마 전환이 가장 단순하다
- 2열 그리드가 F27 grid 레이아웃과 그대로 맞고, 첫 화면에 아이템 4개가 보여 "목록"이라는 감이 가장 강하다
- 글자 대비가 셋 중 가장 높다 (본문 18.6, 보조 6.1, 버튼 6.4 — 라이트 기준)
- 사용자가 매일 보는 화면은 내 목록이고, 그 용도에는 "도구" 쪽 무드가 편하다 (사용자 판단)
- designer는 A를 추천했으나(공유 페이지 콘텐츠 중심·프리셋 내성), B의 약점은 모두 값 조정(글자 크기·배지 테두리·문구)으로 고칠 수 있는 종류라 방향 자체의 결함이 아니다

## 기각된 대안

- **A 따뜻한 종이** — designer 추천안. 공유 페이지 1열 큰 사진이 "콘텐츠가 주인공"에 가장 충실하고 프리셋 배경 변경에 강함. 그러나 1열은 F27 grid용 2열 변형을 따로 그려야 하고, 잡지·큐레이션 무드가 매일 쓰는 목록 화면에는 무겁다
- **C 경쾌한 팝** — 캐주얼 컨셉을 가장 직접 표현하지만 노랑 하나가 칩·받음 배지·가격 3역할을 겸해 "일관된 시스템"에 역행하고, 연보라 배경·보라·노랑이 한 세트라 프리셋 6종마다 토큰 재정의가 필요하다

## 확장 지점

- 토큰은 전부 CSS 변수(`--c-*`, `--r-*`, `--t-*`)로만 쓴다. 팔레트를 통째로 바꾸는 기능(앱 스킨·공유 페이지 프리셋)은 마크업을 건드리지 않고 변수 집합만 교체하는 방식으로 붙인다 — A·C 팔레트는 그 후보로 남긴다
- 핵심 화면 시안은 B 파일의 마크업·토큰을 기반으로 확장한다 (`design/README.md`)
