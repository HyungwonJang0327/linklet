  | 원칙 | 참고 서비스 | Linklet 적용 |
  |---|---|---|
  | 한 화면에 한 가지 일 | 토스 | 화면마다 주된 행동 버튼 하나, 부가 동작은 뒤로 |
  | 단계형 입력 + 기본값 | 토스, Duolingo 온보딩 | 생성 3분 흐름: 한 번에 하나만 묻고 기본값으로 건너뛸 수 있게, 진행 표시 |

  | 저장이 한 동작 | Pinterest(Save), Raindrop | 링크 붙여 넣기 → 미리보기 → 추가까지 한 흐름, 추가 직후 목록에 바로 보임 |
  | 말하듯 쉬운 문구 | 토스, Mailchimp 문체 가이드 | 전문 용어 없이, 버튼은 결과를 말하는 동사("링크 복사하기") |
  | 즉각 피드백 | 토스, Linear | 낙관적 업데이트, 짧은 토스트, 되돌리기(삭제 직후 "실행 취소") |
  | 비어 있음이 안내서 | Notion, Slack | 빈 화면에 다음 행동 하나와 예시 |
  | 폼 실수 방지 | Stripe Checkout | 입력 중 형식 안내, 붙여 넣은 URL 즉시 검사, 오류는 필드 옆에 해결 방법과 함께 |
  | 일관된 시스템 | 애플, Linear | 타이포 단계 적게, 같은 역할은 같은 모양, 라이트·다크 같은 품질 |
  | 절제된 모션 | 애플, Linear | 상태 변화를 설명하는 짧은 전환만, `prefers-reduced-motion` 존중 |
  | 모바일 우선 | 토스, iOS, Instagram | 공유 링크는 메신저에서 열림 → 엄지 닿는 위치의 주요 버튼, 시트형 모달 |
  | 공유 받는 사람도 사용자 | Airbnb 공유 링크, Spotify 공유 카드 | 공유 페이지는 로그인 없이 바로 이해되게, 메신저 미리보기 카드가 곧 첫인상 |

- **UI 리디자인**: v2 화면은 새 시각 디자인으로 만든다. Phase 0에서 ① 시각 방향(무드·레퍼런스) 후보 시안 → 선택 ② 선택한 방향으로 핵심 화면 시안 ③ 시안에서 토큰 추출·결정 순으로 정하고, Phase 1부터는 토큰과 시안을 기준으로 이식한다
  - 시안은 메인이 정적 HTML로 만든다(`design/mockups/`, git 추적). designer는 흐름·접근성·대비를 검토만 한다(에이전트 정의 그대로)
  - 핵심 화면: 랜딩·로그인, 내 위시리스트 목록(4상태), 생성 3분 흐름, 위시리스트 상세(아이템 추가), 공유 페이지(테마 프리셋 2개 이상)
  - 나머지 화면(설정·문의·공지·관리자)은 시안 없이 토큰과 `shared/ui` 로 이식 시점에 만든다

## 이유

- 기반(응답·환경·DB·에러)과 인증을 앞에 두면 이후 기능이 규약을 처음부터 따른다 (FEATURES 순서 원칙)
- 링크 미리보기(Phase 3)는 아이템 추가(Phase 4)의 선행이고 보안 검토가 무거워 따로 둔다
- 기존 파서 출력과 기존 앱 동작을 Phase 0에서 먼저 고정해야 "유지·개선" 행의 동등성을 판정할 수 있다
- 리디자인을 토큰보다 먼저 정하는 이유: v2는 모든 화면을 어차피 새로 만들므로, 방향을 먼저 정하면 이식하며 만든 화면을 다시 고칠 일이 없다. 토큰은 시안에서 추출해야 실제 화면에 맞는 값이 된다
- 첫 배포를 공유(Phase 5)에 맞추면 완료 기준 2(메신저 미리보기)를 실제 URL로 바로 확인할 수 있고, 사용자 작업(Neon·Vercel)을 한 번에 몰아 처리한다

## 기각된 대안

- **첫 배포를 Phase 1 끝으로 앞당김** — 배포 파이프라인을 일찍 검증하지만, 보여줄 화면이 없는 상태에서 Neon·Vercel 사용자 작업과 무료 한도 소모가 앞당겨진다
- **전 Phase를 처음부터 커밋 단위로 세분화** — 앞 Phase에서 정해지는 것(id 방식·토큰·인증 콜백 경로)에 따라 뒤 항목이 바뀌어 다시 써야 한다
- **주당 10시간 기준 기간 산정** (2026-10-04 채택 → 2026-10-05 폐기) — 투입 시간이 일정하지 않아 날짜가 의미를 잃는다
- **리디자인 없이 토큰만 새로** — 가장 빠르지만 화면마다 이식 시점에 즉흥적으로 만들어 일관성이 리뷰에만 의존한다
- **기능 이식 후 별도 리디자인 Phase** — 화면을 두 번 만든다
- **시안을 사용자가 Figma로** — 사용자 작업량이 크고, 시안과 코드 토큰 사이 변환이 한 번 더 필요하다
- **레퍼런스만 고르고 시안 없이** — 화면 구조(3분 흐름·공유 페이지)를 코드로 짜 보기 전에는 확인할 수 없다

## 확장 지점

새 기능은 FEATURES에 행을 추가하고 순서 열에 맞는 Phase에 넣는다. Phase를 추가·병합하면 이 표와 `todo/mvp-todo.md` 를 함께 고친다.
