# 설정 메뉴 구조와 글로벌 내비게이션

## 결정

**설정 허브 + 항목별 페이지** (iOS 설정 패턴). `decisions/url-design.md` 경로 표는 바꾸지 않는다.

### 설정 허브 `/{locale}/settings`

그룹별 행 목록. 행은 하나의 `<a>`(로그아웃만 `<button>`), 높이 44px 이상, 그룹 제목은 `<h2>`.

| 그룹 | 행 | 이동 | FEATURES |
|---|---|---|---|
| 계정 | 프로필 | `/settings/profile` | F28 |
| | 로그인 기기 | `/settings/sessions` | F32 |
| 화면 | 화면 설정 — 행 끝에 현재 값(예: "캔버스 · 시스템 · 한국어") | `/settings/appearance` | F29 |
| 도움말 | 공지 | `/notices` | F31 |
| | 문의 | `/help` | F30 |
| — | 로그아웃 | 버튼 | F08 |

- **모바일**: 허브는 목록만. 행 탭 → 전체 화면 상세, 상세 상단에 "설정으로" 뒤로 가기 링크 필수. 허브에는 목록 화면의 하단 고정 버튼이 나오지 않는다
- **데스크톱**: 상세 페이지는 2단 — 같은 허브 목록이 왼쪽 열(사이드바)로 렌더, 현재 항목 `aria-current="page"`. 허브와 사이드바는 **한 컴포넌트**. `/settings` 자체는 뷰포트와 무관하게 허브 목록을 렌더(뷰포트별 리다이렉트 없음)
- 사이드바 폭은 한국어 기준으로 고정하지 않고 2줄 허용 (ja "ログイン中の端末"이 가장 길다)

### 꾸미기(F27)의 진입점

설정 메뉴에 두지 않는다. 위시리스트 상세 페이지의 "꾸미기" 버튼 하나 → `/wishlists/{id}/customize`. 설정에 넣으면 "어느 위시리스트?" 선택 단계가 생긴다 (기존 앱 `settings/customize` 가 그 구조였다)

### 글로벌 내비게이션

| 뷰포트 | 구성 |
|---|---|
| 모바일 | 워드마크 + 아바타 버튼(탭하면 `/settings` 허브로 이동, 드롭다운 없음) |
| 데스크톱 | 워드마크 + "위시리스트 · 설정" 링크 + 아바타(같은 곳) |

공지·문의는 글로벌 nav에 두지 않고 설정 허브 "도움말" 그룹에만 둔다.

## 이유

- 모바일 우선 원칙에서 가장 익숙한 설정 패턴. "한 화면 한 가지 일" — 상세 페이지마다 폼 하나·저장 하나
- 허브 목록이 데스크톱에서 사이드바가 되므로 "사이드바 유지 여부"는 "모양은 유지, 모바일 허브와 같은 컴포넌트"로 답한다
- 공지·문의·로그아웃처럼 성격이 다른 항목을 설정 '페이지'로 만들지 않고 목록 '행'으로만 두어 경로 표를 한 줄도 바꾸지 않는다
- 드롭다운 메뉴를 만들지 않으면 키보드·포커스 복귀 검증 대상이 하나 준다 (§4-3)
- 공지·문의는 핵심 시나리오(담기·공유)에 필요 없는 항목이다

## 기각된 대안

- **단일 설정 페이지 섹션 스크롤** — 코드는 최소지만 `/settings/profile·appearance·sessions` 경로를 폐기하거나 해시로 바꿔야 하고, 저장 버튼이 섹션마다 생기며, 파괴적 동작("다른 기기 모두 로그아웃")이 프로필 폼 바로 아래 놓인다
- **상단 탭** (프로필 / 화면 / 기기) — 공지·문의·로그아웃이 탭에 못 들어가 진입점이 또 필요하다. 탭은 U4에서 URL 쿼리 상태 패턴이라 페이지 이동과 충돌. ja 탭 폭 편차
- **기존 사이드바 유지** (햄버거 드로어 + 접히는 사이드바) — 접기 버튼 라벨 없음, 관리자 기능이 사용자 설정에 섞임, 위시리스트 메뉴가 설정 아래 → 리뉴얼 제거 대상

## 확장 지점

- 설정 항목 추가 = 허브 표에 행 1개 + 페이지 1개. 그룹을 벗어나면 새 그룹 제목을 추가한다
- 데스크톱에서 `/help`·`/notices` 가 설정 2단 레이아웃을 공유할지는 F30·F31 이식 때 라우트 그룹 배치로 정한다. 독립 페이지로 두어도 UX상 문제 없음
