대상: $ARGUMENTS (비우면 전체 행)

1. `audit/FEATURES.md` 를 읽는다
2. 행마다 실제 상태를 확인한다
   - `v2/` 에 구현이 있는가 (라우트·feature 폴더·API)
   - "동등성 확인 방법"의 테스트가 존재하고 통과하는가 (해당 테스트만 실행)
   - 수동 확인 항목은 worklog에 확인 기록이 있는가
3. 상태 열을 근거와 함께 갱신한다: `미착수` → `이식 중` → `이식 완료` → `동등성 확인` → `기존 제거`
   - 근거 없이 상태를 올리지 않는다. 테스트가 실패하면 `이식 완료` 에 머문다
4. 보고
   - 진행률: 처분별(유지·개선·재설계·신규) 완료 수 / 전체
   - 동등성 미확인 목록 (ID, 막힌 이유)
   - 대체됐는데 아직 남은 기존 코드 목록 (ID → 루트 파일 경로) — 교체 시점 제거 대상
   - 다음에 이식할 행 3개 (이식 순서 열 기준)
5. FEATURES.md 변경을 커밋한다: `docs(audit): 이식 상태 갱신`. push하지 않는다
