# FEATURES — 리뉴얼 완료 판정표

- 기준: `audit/FEATURES-before.md`(리뉴얼 전 기능 목록) + 1단계 인터뷰(`worklog/2026-09-27.md`) + `INTENT.md`
- 전략: 병행 재구축(`decisions/renewal-strategy.md`) — `v2/` 에 이식, 교체 시점에 기존 코드 일괄 제거
- 처분
  - **유지**: 같은 입력에 같은 결과
  - **개선**: 같은 목적, 감사에서 나온 결함을 고친 결과 (바뀌는 동작은 이유 열에 근거)
  - **재설계**: 동작·UX가 의도적으로 바뀜 (새 동작 기준으로 확인)
  - **삭제**: v2로 옮기지 않음. 영향 범위와 대체 여부를 적음. "언젠가"는 todo에 보관
  - **신규**: 기존에 없던 것
- 이식 순서: 숫자가 작을수록 먼저. 같은 숫자는 순서 무관. 다른 기능이 기대는 기반(환경·DB·레이아웃·에러·인증)을 앞에 둔다
- 동등성 확인: `E2E:` Playwright 시나리오 / `단위:` Vitest / `수동:` 체크 절차. 테스트 이름은 이식 시 확정
- 상태: `미착수` → `이식 중` → `이식 완료` → `동등성 확인` → (교체 후) `기존 제거`. `/parity` 가 갱신한다
- ⚠ **확정 필요** 표시 행은 표 아래 질문의 답에 따라 처분이 정해진다
